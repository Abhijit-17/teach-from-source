Lesson 0001

Recall check: how does a replica keep the data? Lesson 0000

Answer

It keeps a copy of the data.

A replica keeps a copy of the data. When the data changes, the leader sends the new value to each replica.

Martin Kleppmann tells you how a replica keeps the data. Use SET key value; GET key; DEL key; SET key other value; GET key; DEL key; SET key value to see the value.

Use r = n - f to get the number of replicas (p. 12).

  1. Read the value from the leader.

Problem

A node can stop.

Ground truths

A node can stop at any time.

Outside the source: not from your registered sources. Logged as a Gap.

A copy of the data can be on two nodes.

Build-up

If one node stops, the other node keeps the data.

Name

This copy is a replica.

Foundation test

If a node does not stop, you do not need a replica.

Data outlives code; that is the problem, and it's a hard one to solve well.Kleppmann, ch. 1
